# Calendar (Этап 2 — SQLite)

## Сборка на Linux

```bash
sudo apt update
sudo apt install build-essential cmake qt6-base-dev libqt6sql6-sqlite

mkdir build && cd build
cmake ..
make -j$(nproc)
./QtCalendarApp
```

`libqt6sql6-sqlite` — это отдельный пакет с драйвером SQLite для Qt SQL
(на Debian/Ubuntu он не входит в `qt6-base-dev`). Без него `EventManager`
не сможет открыть базу — в консоли будет предупреждение вида
`QSqlDatabase: QSQLITE driver not loaded`.

Если `cmake ..` не находит Qt6 (например, Qt установлен через онлайн-инсталлятор
в нестандартный путь), укажите путь явно:

```bash
cmake .. -DCMAKE_PREFIX_PATH=/путь/до/Qt/6.x.x/gcc_64
```

## Где хранятся данные

База — файл `calendar.db` в стандартной папке данных приложения
(обычно `~/.local/share/QtCalendarApp/calendar.db` на Linux). Чтобы
начать «с чистого листа», можно просто удалить этот файл — при
следующем запуске он будет создан заново пустым.

## Импорт расписания из CSV

`File → Import CSV...`. Ожидаемый формат (первая строка - заголовок,
всегда пропускается):

```csv
date,start,end,subject,description
15.09.2026,09:00,10:30,Математика,Алгебра
```

- Дата: `dd.MM.yyyy`, время: `HH:mm`.
- Строки с ошибками (кривая дата/время, не то число столбцов, конец раньше
  начала, пустое название) пропускаются, а не останавливают весь импорт -
  в конце показывается, что именно было пропущено и почему.
- В `examples/schedule-sample.csv` лежит тестовый файл с несколькими
  корректными записями и несколькими намеренно битыми строками - удобно
  проверить оба сценария сразу.

## Уведомления (Этап 7)

Показ через системный трей (`QSystemTrayIcon`) - в трее появится маленькая
иконка, через неё же приходят уведомления.

- **Напоминание о событии**: раз в 30 секунд проверяется, не начинается ли
  какое-то сегодняшнее событие в ближайшие 10 минут. Чтобы быстро проверить -
  создай событие с временем начала на 5-10 минут вперёд от текущего момента
  и подожди до минуты.
- **Pomodoro**: уведомление при каждой смене фазы ("Pomodoro finished" /
  "Break finished"). Проверяется так же, как в Этапе 3 - можно временно
  уменьшить `kWorkMinutes` в `PomodoroTimer.h`, чтобы не ждать 25 минут.

Если в трее не появилась иконка - скорее всего, у твоего окружения рабочего
стола нет системного трея (бывает на некоторых минималистичных DE/WM).
Приложение в этом случае не упадёт, но и уведомлений показывать не будет -
в консоли будет предупреждение `System tray is not available`.

## Настройки (Этап 8)

`File → Settings...`. Хранятся через `QSettings` в
`~/.config/QtCalendarApp/QtCalendarApp.conf`.

- **Pomodoro**: длительности работы/короткого/длинного перерыва -
  применяются к следующей фазе (или сразу, если нажать Reset), без
  перезапуска приложения.
- **Тема** (Dark/Light) и **первый день недели** (Monday/Sunday):
  первый день недели применяется сразу; смена темы требует перезапуска
  приложения (сообщение об этом появится после сохранения настроек).
- **Уведомления**: общий выключатель, проверяется в одном месте
  (`NotificationService`), поэтому сразу отключает и напоминания
  о событиях, и уведомления Pomodoro.
- **Горячие клавиши** (можно переназначить в диалоге настроек):
  - `Ctrl+N` - новое событие
  - `Ctrl+I` - импорт CSV
  - `Ctrl+T` - перейти к сегодняшнему дню
  - `Ctrl+P` - Start/Pause Pomodoro

## Темы оформления (Phase C)

`File → Settings... → Theme`. Доступны: Dark, Light, Purple, Ocean, Forest,
Rose. Применяется сразу по нажатию OK, без перезапуска приложения -
`ThemeManager` красит палитру/QSS всего приложения и оповещает
custom-painted виджеты (сетку месяца) отдельным сигналом, чтобы они
перерисовались со своими цветами. Выбор сохраняется через `AppSettings`
и восстанавливается при следующем запуске.

## Переключатель Month / Week / Day (Phase D)

Над календарём — переключатель представлений. Week и Day пока заглушки
(полноценная временная сетка появится в Phase E/F) — они уже умеют
переключаться и листаться по датам (предыдущая/следующая неделя или день,
Today), просто без карточек событий внутри. В Month View справа видна
панель со списком событий, как раньше; в Week/Day она скрывается —
события там будут показываться прямо внутри сетки.

## Week View (Phase E)

Полноценная временная сетка на 7 дней:

- **Зум**: `Ctrl + колесо мыши` меняет высоту часа (32-160px). Обычное
  колесо - вертикальный скролл.
- **Создание события**: одиночный клик по пустому месту сетки сразу
  открывает создание события с датой/временем по месту клика, округлённым
  до 15 минут.
- **Выбор события**: одиночный клик по событию только выделяет его
  (рамка акцентным цветом) - никуда не перемещает и не открывает.
- **Редактирование**: двойной клик по событию открывает тот же
  `EventDialog`, что и везде в приложении.
- **Пересекающиеся события**: раскладываются рядом по "дорожкам"
  (простой алгоритм, см. `ui/EventLayout.*`), а не друг на друге.
- **Текущее время**: тонкая линия с точкой в колонке сегодняшнего дня.
- При открытии неделя сразу прокручена к 7:00, а не к полуночи.

Drag (перемещение мышью) и resize (изменение длительности) - в Phase G/H,
сознательно не в этой фазе.

Общий "движок" сетки (`ui/TimeGridView.*`) не привязан к недельному
представлению - в Phase F Day View будет использовать тот же класс всего
с одной колонкой вместо семи.

## Day View (Phase F)

Тот же `TimeGridView`, что и в Week View, просто с одной колонкой -
масштаб, скролл, создание по клику, выбор/редактирование событий,
текущее время - всё работает одинаково. Навигация - по дням, заголовок -
"Wednesday, 16 September 2026".

## Важно про сборку на Windows/MinGW

Если встретишь ошибку вида `expected unqualified-id before '=' token` на
строке с переменной `slots` - это не баг в логике, а конфликт имени
переменной с зарезервированным макросом Qt (`slots` разворачивается в
`Q_SLOTS`, используется в объявлениях `public slots:`/`private slots:`).
Не называй локальные переменные `slots` - используй, например, `eventSlots`.

## Импорт недельного расписания (второй формат CSV)

Помимо простого формата `date,start,end,subject,description`, `File → Import
CSV...` теперь понимает и формат внешних приложений-плановщиков:

```
TYPE,CONTENT,DESCRIPTION,PRIORITY,INDENT,DATE,DATE_LANG,TIMEZONE,DURATION,DURATION_UNIT
task,Подъём и разминка,Вода + разминка,3,2,every monday at 06:20,ru,Europe/Moscow,10,minute
```

Формат определяется автоматически по строке заголовка - ничего выбирать
вручную не нужно.

- `section` - не событие, пропускается молча (это просто группировка вроде
  "Понедельник" в исходном файле).
- `task` с `DATE` вида `every <день недели> at HH:MM` становится **одним**
  повторяющимся событием (`RecurrenceType::Weekly`) - как и остальные
  повторяющиеся события в приложении, не хранится как N отдельных записей
  на каждую неделю. Дата импорта ни на что не влияет - подходит любой год.
- `DURATION` + `DURATION_UNIT` (minute/hour) считают время окончания.
- `PRIORITY` и `TIMEZONE` сохраняются в событии (новые поля `Event::priority`,
  `Event::timezone`), но пока не используются нигде в логике - только чтобы
  не терять эти данные при импорте, как и просили.
- Если в `DESCRIPTION` встречается незаэкранированная запятая (например,
  "1,5 ч" - частая ошибка ручных CSV-экспортов), импортёр аккуратно
  восстанавливает поле, только если после восстановления `PRIORITY` и `DATE`
  действительно оказываются на своих местах - иначе показывает обычную
  ошибку "не то число столбцов", а не гадает вслепую.

Тестовый файл с полным расписанием (93 задачи на 7 дней недели, включая все
проблемные строки с запятыми) - `examples/weekly-schedule-sample.csv`.

## Исправление: обёрнутые в кавычки строки + Windows-1251 (повторный баг CSV)

Два отдельных исправления в `CsvImporter`:

1. **Строки, целиком обёрнутые во внешние кавычки.** Некоторые экспортёры
   (замечено на реальном файле) оборачивают всю CSV-запись ещё в одну пару
   кавычек поверх обычного экранирования:
   `"task,""Душ, завтрак, сборы"",,4,2,..."`. Обычный разбор видит такую
   строку как одно поле. Добавлен fallback (не отдельный parser, а просто
   повторный вызов того же `parseCsvContent()` на этом единственном поле) -
   стандартные строки без такой обёртки он не трогает.
2. **Кодировка Windows-1251.** Файлы, сохранённые не в UTF-8 (частый случай
   на Windows), теперь определяются и читаются корректно: UTF-8 BOM → UTF-8
   → попытка строгого UTF-8 → иначе Windows-1251 (через встроенную таблицу
   байт→Unicode, без дополнительных Qt-модулей).

Тестовый файл — именно тот, что был приложен к багрепорту:
`examples/calendar-cp1251-wrapped.csv`.
